# 2. SaaS형 Apache Kafka 장점과 단점

### 장점

1. **인프라 관리의 효율화**
	- 카프카 클러스터는 최소 3대 이상의 서버로 운영
		- 이걸 모니터링 해야함
	- SaaS를 사용하면 인프라 운영 관련 역할에서 자유로움
	- 클러스터 개수를 늘려야하는 경우에도 SaaS 대시보드에서 브로커 개수만 설정하면 Scale-out이 쉬움

2. **모니터링 대시보드 제공**
	- 브로커들이 제공하는 지표들을 수집, 적재하고 대시보드화 해야함
		- 필요한 설정을 수정 -> 적용 해야함
	- SaaS형 카프에서는 자동화되어 만들어진 클러스터의 운영 지표를 그래프로 보여주는 옵션이 제공
		- 직접 운영하면 모니터링 붙여야함

3. **보안 설정**
	- 보안이 없는 클러스터는 호스트와 포트 번호만 알면 모든 토픽 데이터를 가져갈 수 있음..
	- 카프카 브로커는 SSL, SASL, ACL같은 보안 설정이 있음
		- 그러나 선택하고 운영하는 것도 어려움..
	- SaaS 카프카는 기본적으로 보안 설정 제공


### 단점

1. **서비스 사용 비용**
	- 직접 운영 -> 브로커(+주키퍼) 실행 서버 비용만 내면 됨
	- SaaS -> 요금제를 사용
		- ex) AWS MSK : 3대 브로커(CPU 4, 메모리 16GB) -> 한달에 120만원

2. **커스터마이징 제한**
	- 서버의 최적화 옵션이나 브로커 옵션을 상세하게 할 수가 없음
	- 특히 멀티 클라우드(2개 이상의 퍼블릭 클라우드), 하이브리드 클라우드(사내 서버+클라우드)
		- <mark class="hltr-yellow">이건 SaaS형 카프카에서는 불가능</mark>

3. **클라우드 종속성**
	- 프로듀서, 컨슈머들을 포함한 클러스터와 관련된 모든 애플리케이션이 해당 서비스에 종속
		- 중간에 옮기기도 어려움

### 그럼에도..

카프카 클러스터에 대한 충분한 이해를 가진 상태에서 SaaS를 이용하는 것이 효과적임
현재 인력의 카프카 클러스터 운영에 대한 이해의 깊이, 클러스터 구축 비용, 추후 운영상 이슈를 고려하자!
