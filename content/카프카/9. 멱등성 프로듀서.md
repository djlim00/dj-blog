# 1. 멱등성 프로듀서

### 1. 전달 신뢰성

- 멱등성 : 여러 번 연산을 수행해도 동일한 결과.
- <mark class="hltr-yellow">멱등성 프로듀서 : 동일한 데이터를 여러 번 전송하더라도, 카프카 클러스터에 단 한 번만 저장됨.</mark>
	- 기본 동작은 "적어도 한번 전달(at least once delivery)"
	- 이건 중복 저장이 가능한 형태라서 멱등성이 지켜지지 않음.

1. At least once : 적어도 한번 이상
2. At most once : 최대 한번 
3. Exactly once : 정확히 한번 전달

### 2. 멱등성 프로듀서
![[Pasted image 20260720115338.png]]

- 데이터 중복 적재를 막기 위해서 `enable.idempotence` 옵션이 있음 -> <mark class="hltr-yellow">Exactly once delivery</mark>


![[Pasted image 20260720115432.png]]

1. 멱등성 프로듀서는 기본 프로듀서와 다르게 `프로듀서 PID` 와 `시퀀스 넘버` 를 한께 전달.
2. 이 두 값이 같으면 이미 처리한 데이터를 처리하지 않음.

## 멱등성 프로듀서의 한계

- <mark class="hltr-yellow">동일한 세션에서만</mark> 정확히 한번 전달을 보장.
	- 세션 : PID의 생명주기
	- 만약 프로듀서에 이슈가 생겨서 재시작하면 PID가 달라짐 -> 중복 저장이 가능해짐.


### 멱등성 프로듀서로 설정하면 자동 옵션

- retries(재전송 횟수) => MAX_VALUE가 된다.
- acks 옵션은 all이 된다.

=> 프로듀서가 적어도 한 번 이상 브로커에 데이터를 보냄으로써 브로커에 단 한 번만 데이터가 적대되었다는 것을 보장하기 위해서.


#### 멱등성 프로듀서 사용시 오류 확인

![[Pasted image 20260720115724.png]]

- `시퀀스 넘버` : 0에서 시작해서 1++
	- 시퀀스 넘버가 일정하지 않으면 `OutOfOrderSequenceException` 발생
	- <mark class="hltr-yellow">이를 처리하는 로직이 있어야한다.</mark>

# 2. 트랜잭션 프로듀서, 컨슈머

## 1. 트랜잭션 프로듀서 

![[Pasted image 20260720115853.png]]

- 카프카의 트랜잭션은 다수의 파티션에 데이터를 저장하는 경우, 모든 데이터에 대해 동일한 원자성을 만족시키기 위해 사용
	- "원자성을 만족" == <mark class="hltr-yellow">다수의 데이터를 동일 트랜잭션으로 묶음으로써 전체 데이터를 처리하거나 전체 데이터를 처리하지 않도록 하는 것을 의미</mark>
- 트랜잭션 프로듀서는 사용자가 보낸 데이터를 레코드로 파티션에 저장 + 트랜잭션의 시작/끝을 표현하기 위해 트랜잭션 레코드를 한 개 더 보낸다.

## 2. 트랜잭션 컨슈머

![[Pasted image 20260720120116.png]]

- 파티션에 저장된 <mark class="hltr-yellow">트랜잭션 레코드를 보고, 트랜잭션이 Commit 되었음을 확인하고 데이터를 가져감</mark>.
- 트랜잭션 레코드는 실질적 데이터는 없고, Commmit 여부만 있음.
