# 3. ISR (In-Sync-Replicas)와 acks 옵션

- ISR은 리더 파티션과 팔로워 파티션이 모두 싱크가 된 상태
	- 즉 리더 파티션의 오프셋이 팔로워 파티션에 전부 존재해야함
- 복제에는 시간이 걸리기 때문에, 나온 용어
- 프로듀서가 특정 파티션에 데이터를 저장하는 작업 -> 리더 파티션을 통해서 한다.
	- 만약 리더 파티션에 샐운 레코드가 추가되서 오프셋이 증가하면 -> 팔로워 파티션이 위치한 브로커는 리더 파션의 데이터를 복제
	- 리더 적재 <mark class="hltr-yellow">이후</mark> 팔로워 파티션에 복제하는 시간차가 발생하기 때문에 파티션 간의 오프셋 차이가 발생


- acks 옵션은 0, 1, all(또는 -1)
- 얼마나 신뢰성 높게 저장할지 지정 가능
- <mark class="hltr-yellow">acks옵션에 따른 카프 동작 방식을 상세히 알고 설정해야함</mark>


### 안정적인 데이터 운영을 위한 복제 개수 2 이상인 경우의 acks별 동작 방식

- 0은 리더 파티션이 방금 받은 데이터의 오프셋 값에 대한 응답값을 받지 않음 -> 훨씬 빨라짐
- 데이터 유실이 발생해도 속도가 중요한 경우


- 1은 0의 반대 경우이다.
- 만약 리더에 적재되지 않았다면, 리더 파티션에 적재될 때까지 재시도할 수 있음.
- 이래도 데이터 유실 가능
	- 만약 리더의 데이터를 팔로워가 아직 복제(동기화) 안했는데, 리더 파티션의 브로커가 장애나는 경우


- 0과 1의 경우를 전부 만족한 경우
- 속도가 느림
- 이런 경우는 replicas 값이 데이터의 안정성의 최후의 조건이 된다.(5개면 3개가 죽어도 괜찮지만, 3개면 3개가 죽으면 안됨)

- 즉 min.insync.replicas의 옵션값이 2이상일 때만 의미가 있다 -> 리더랑 팔로워가 있어야하니까.
- 브로커 2개가 동시에 중단되는 일은 극히 드물기 때문에
